# iOS integration handoff

`ios/` belongs to the separate iOS implementation. This scaffold adds only `.gitkeep`; no Swift files, Xcode project, generated client, entitlements, or app identifiers have been created.

## Shared contract

The backend's Zod schemas and Hono routes generate `contracts/openapi.yaml` (OpenAPI 3.1). Use that file with Swift OpenAPI Generator; do not maintain a second copy of network DTO definitions. Run `make openapi` after route changes. CI rejects contract drift. A running copy is served at `/openapi.json`.

The development server is `http://localhost:3000`. Override that URL in the generated client rather than embedding it in release builds. See `development.md` for physical-device networking.

## Authentication

Better Auth owns `/api/auth/*`; these provider endpoints are separate from the generated domain contract. Native Apple sign-in submits its Apple identity token to `POST /api/auth/sign-in/social`:

```json
{
  "provider": "apple",
  "idToken": { "token": "APPLE_IDENTITY_TOKEN", "nonce": "ORIGINAL_NONCE" }
}
```

Coordinate the Apple nonce flow with Better Auth's provider contract, retain Apple's one-time name/email information as needed, and never skip ID-token verification. The server needs `APPLE_CLIENT_ID`, `APPLE_CLIENT_SECRET` (the signed Apple client-secret JWT), and `APPLE_APP_BUNDLE_IDENTIFIER`. No identifiers have been invented. The configured bundle identifier enables native audience validation. Real Apple sign-in requires credentials and has not been exercised by scaffold tests.

For local development, `.env` enables Better Auth email/password accounts. Create a disposable account:

```sh
curl --fail-with-body http://localhost:3000/api/auth/sign-up/email \
  -H 'Content-Type: application/json' \
  -d '{"name":"Local Athlete","email":"athlete@example.test","password":"local-development-password"}'
```

Sign in subsequently using `POST /api/auth/sign-in/email` with the email/password. Use the returned `token` as `Authorization: Bearer TOKEN`; the bearer plugin also exposes `set-auth-token`. Store real session tokens in Keychain. Sign out using `POST /api/auth/sign-out`. This is ordinary session authentication, not an auth bypass, and `DEV_AUTH_ENABLED=true` is rejected in production.

## Working endpoints

| Endpoint | Behavior |
| --- | --- |
| `GET /health/live` | Process health; public |
| `GET /health/ready` | Database health; public |
| `GET /v1/bootstrap?deviceId=UUID` | Current athlete, this installation's registration, policy, entitlements, sync capability |
| `GET /v1/config/training-policy` | Published policy, `ETag`, `If-None-Match` / 304 |
| `PUT /v1/devices/{deviceId}` | Idempotent full registration; UUID generated by installation |
| `DELETE /v1/devices/{deviceId}` | Repeatable revocation and removal of push token |
| `GET /v1/billing/entitlements` | Current stored entitlement records; empty means no grant |

All `/v1` endpoints require a session. Athlete ownership is inferred from that session and cannot be supplied in the body. New users are provisioned with UTC, metric units, English, and Monday as neutral defaults; editable onboarding/sync is still to come.

Device PUT replaces registration metadata; include the token when `pushEnabled` is true. Bootstrap reports `device.registered: false` if `deviceId` is omitted. No push is actually delivered yet.

## Unfinished contracts

Sync push/pull, remote decisions/chat, StoreKit verification, and account deletion return `501 NOT_IMPLEMENTED`. Their request envelopes are provisional; successful responses are intentionally absent from OpenAPI. Do not delete outbox mutations or advance a sync cursor on these responses. Bootstrap explicitly reports `sync.available: false`.

The development policy sets feature flags to false; it is not a training prescription. Cache policies only when the client supports their schema version. The actual training domain and mutation payloads will be introduced in follow-up migrations/contracts.

## Data conventions

- Client-created domain IDs and installation IDs use UUID strings.
- JSON field names use camelCase.
- Cursors/revisions are decimal strings, preserving PostgreSQL bigint precision. This intentionally refines the architecture's illustrative numeric JSON examples.
- Use explicit athlete training dates and IANA zones, independently from UTC instants.
- Future canonical units: integer meters and seconds; decimal kilograms. Keep planned and actual performance distinct.
- Errors use `{ "error": { "code", "message", "details"?, "requestId" } }`; branch on `code`, not prose. `X-Request-Id` correlates errors with server logs. Better Auth retains its own error format.

HealthKit normalization, training calculations, candidate generation, local scheduling, SwiftData, outbox persistence/retries, local notifications, and the native UI remain iOS responsibilities.
